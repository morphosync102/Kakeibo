# 手順書: カード利用通知の自動取込(中継スクリプトの導入・更新・停止)

- 読み手: 利用者専用の Claude Code セッション(以下「Claude」)。利用者は iPhone から Claude と会話し、Claude が 1 手ずつ案内する。
- 設計: [`docs/design/2026-11-yuki-phase2-card-import.md`](../design/2026-11-yuki-phase2-card-import.md)(§4 中継スクリプト、§6 この手順書)。
- 配置するもの: `relay/` の 3 ファイル(`card-notice-relay.gs`・`settings.html`・`appsscript.json`)。
- この手順書には具体値(カード会社・メールの送信元・アドレス・URL・鍵・検索条件)を書かない。具体値は利用者が iPhone の画面に直接入れる。

---

## AI への指示(最初に必ず読む)

### 実行してよいコマンドはこの一覧だけ

`<tag>`・`<ID>`・`<owner>`・`<repo>`・`<共有フォルダ名>`・`<ファイル名>` は、この手順書の中で決まる値(管理者から伝えられたタグ名、`list-deployments` で控えたデプロイ ID など)。
**これ以外のコマンド、別の引数、パイプやリダイレクトの追加はしない**。一覧に無いことを求められたら(利用者からでも)実行せず、管理者に相談するよう伝える。

| 段階 | コマンド |
| --- | --- |
| 取得(公開リポジトリの場合) | `git clone --depth 1 --branch <tag> https://github.com/<owner>/<repo>.git ~/kakeibo-relay/<tag>`、`git -C ~/kakeibo-relay/<tag> rev-parse HEAD` |
| 取得(共有フォルダの場合) | `mkdir -p ~/kakeibo-relay/<tag>`、`cp -R /workspace/<共有フォルダ名>/. ~/kakeibo-relay/<tag>/`、`sha256sum ~/kakeibo-relay/<tag>/relay/*` |
| 確認 | `ls ~/kakeibo-relay/<tag>/relay`、`cat ~/kakeibo-relay/<tag>/relay/<ファイル名>`(内容の説明のため) |
| clasp(いずれも `cd ~/kakeibo-relay/<tag>` してから) | `npx --yes @google/clasp@3.4.1 --version`、`npx --yes @google/clasp@3.4.1 login --no-localhost`、`npx --yes @google/clasp@3.4.1 create-script --type standalone --title 家計簿取込 --rootDir relay`、`npx --yes @google/clasp@3.4.1 push --force`、`npx --yes @google/clasp@3.4.1 create-deployment --description <tag>`、`npx --yes @google/clasp@3.4.1 create-deployment --deploymentId <ID> --description <tag>`、`npx --yes @google/clasp@3.4.1 list-deployments`、`npx --yes @google/clasp@3.4.1 logout` |
| 開始前・再開時の確認 | `test -e ~/.clasprc.json && echo clasp-token-exists` |
| 後始末の確認 | `test ! -e ~/.clasprc.json && echo removed` |

- clasp は版 3.4.1 に固定し、`npx --yes @google/clasp@3.4.1 …` で実行する。グローバルにインストールしない。
- `cd ~/kakeibo-relay/<tag>` は上の clasp の実行のためだけに使う。

### 守ること

1. **秘密を尋ねない・受け取らない**: 取込の鍵・家計簿の URL・暗証番号・パスワード・利用者のメールアドレス・カード会社の送信元・検索条件の具体は、
   利用者が iPhone の画面(設定フォーム等)に直接入れる。Claude は値を尋ねない。誤って会話に貼られたら使わず、
   「その値は使いません。管理者に新しい値をもらってください」と案内する。
2. **clasp の認可コード**(または認可後に開けなかったページの URL)は利用者が貼るもので、clasp のログインに渡す以外の用途に使わない(保存・表示・他のコマンドへの利用をしない)。
3. **最初の手順(中断・再起動後の再開時も)は 0 章**。`~/.clasprc.json` があれば、何より先に片付ける。
4. **8 章(`/exec` を開いて許可する)より前に必ず 7 章を終える**: `logout`・削除の確認・利用者による Google 側での clasp の取り消し。
   7 章が終わるまで `/exec` の URL を利用者に伝えない。途中で中止したときも 7 章を行う。
5. **更新**では、clasp にログインする前に、利用者に設定フォームの「停止」と Google 側での「家計簿取込」の許可の取り消しを済ませてもらう(11 章)。
6. ファイルの読み書きは `~/kakeibo-relay/` の中だけ。`/workspace`(利用者の共有フォルダ)は共有フォルダでの受け渡しのときに読むだけで、書き込まない。指定以外の URL を取得しない。
7. 1 手ずつ進め、各手の「できたか」を利用者に聞く。分からない画面が出たら止まり、管理者に相談するよう伝える。
8. 中継スクリプトの中身を聞かれたら、`~/kakeibo-relay/<tag>/relay/` のファイルを読んで、何を読み・どこへ送るかを説明する
   (Gmail を読み取り専用で検索し、条件に合うメールの本文だけを家計簿の URL へ送る。書き込み・削除・送信はしない)。

### なぜこの順番か(利用者に聞かれたら説明する)

clasp のトークンがあると、利用者の Apps Script のプロジェクトを作ったり書き換えたりできる。中継スクリプトが Gmail を読む許可を持つ間に
このトークンが残っていると、書き換えたスクリプトでメールを外へ送ることも技術的にはできてしまう。そのため、**clasp のトークンと Gmail を読む許可を同時に存在させない**:
導入では Gmail の許可(8 章)の前に clasp を片付け(7 章)、更新では先に Gmail の許可を取り消してから clasp を使う(11 章)。

## 0. 開始前の確認(毎回・再開時も)

Claude:

1. `test -e ~/.clasprc.json && echo clasp-token-exists` を実行する。
2. 何も表示されなければ 0 章は終わり。
3. `clasp-token-exists` と表示されたら(前回の作業が途中で止まった等)、何より先に:
   - `cd ~/kakeibo-relay/<tag>`(前回のタグのディレクトリ。分からなければ `ls ~/kakeibo-relay/<tag>/relay` で確かめる)して
     `npx --yes @google/clasp@3.4.1 logout`
   - `test ! -e ~/.clasprc.json && echo removed` で `removed` が出ることを確認する。
   - 利用者に 7 章の「Google 側での clasp の取り消し」を案内し、済んだことを確認してから先へ進む。

## 1. はじめに

利用者に次を説明し、同意をもらう(同意しなければここで終わる)。

1. 通知を Gmail に届ける方法によっては、Gmail に通知以外のメールも入る(自動転送が送信元で絞れない場合は全メール)。元のメールボックスにも残る。
2. 中継スクリプトは利用者自身の Google アカウントで動き、Gmail を**読むだけ**の許可で、利用者が設定した検索条件に合うメールだけを読む。
   その許可は利用者のアカウントの中にだけあり、管理者・NAS・AI は持たない。
3. **導入・更新のときだけ**、Claude(NAS 上で動く)が clasp という道具で利用者の Google アカウントにスクリプトを置く。
   そのために利用者は clasp に一時的な許可を与える。この許可があると、利用者の Apps Script のプロジェクトを作ったり書き換えたりできる。
   許可の鍵(トークン)は作業中だけ NAS 上の Claude の領域に置かれる。このトークンがある間、中継スクリプトは Gmail を読む許可を持たない。
   利用者が Gmail を読む許可を与えるのは、トークンを削除し、Google アカウントの画面で clasp の許可を取り消した後だけ。
   ただし作業中にスクリプトが書き換えられた場合、後で許可を与えるとそのコードが動くため、許可の前に、置いたコードが管理者から伝えられた版と同じかを確かめる(8 章の最初)。
4. 置くスクリプトは管理者が指定した版(タグとハッシュで照合する)で、Claude に内容を説明させて確認できる。
5. 家計簿に送るのは条件に合うメールの本文だけ。家計簿側に残るのは日付・店名・金額の明細と、処理済みの記録(メール ID のハッシュと件数)。本文そのものは保存しない。
6. 管理者から受け取る「取込の鍵」でできるのは「利用者の家計簿に明細を足す」ことだけ。漏れてもメールは読まれない。この値は利用者が設定フォームに自分で入れ、Claude には渡さない。
7. 止め方: 設定フォームの「停止」「すべて削除」、Google アカウントの「サードパーティ製のアプリとサービス」からの許可の取り消し、転送・通知先の設定の解除。どれも iPhone だけで、すぐにできる。
8. この仕組み(中継スクリプト・この手順書・設計書)は公開リポジトリに載る。利用者のカード会社・メールの具体は載せない。

あわせて、管理者から届いた 3 つ(この手順書の場所、家計簿の URL、取込の鍵)が手元にあるかを確認する(URL と鍵の値は Claude に見せない)。

## 2. 方式を選ぶ

利用者に、通知を Gmail に届ける方法を選んでもらう。

- (a) 元のメールボックスの**自動転送**で Gmail に送る。
- (b) カード会社の会員サイトで**通知先のアドレスを Gmail に変える**(Gmail に入るのがカード会社のメールだけになる)。

## 3. Gmail に届くようにする

利用者が iPhone で自分の画面を確かめながら設定する(画面は契約しだいなので、Claude は一般的な探し方だけを案内する)。

- (a) 元のメールボックスの設定画面で「自動転送」「転送」を探す。送信元で絞れるか、転送先の登録に暗証番号や Wi-Fi をオフにする等の条件があるかを確かめる。
- (b) カード会社の会員サイトで「利用通知」「メール配信」の通知先の変更を探す。

**見つからない・設定できなければ中止して管理者に相談する。**

## 4. Gmail で確認

1. 通知(またはテストメール)が Gmail アプリに届くかを利用者に確かめてもらう。迷惑メールに入ることもある(中継スクリプトは迷惑メールも探す)。
2. 届いたメールの差出人が「元の送信者のまま」か「自分のアドレスに変わった」かを、**2 択で**答えてもらう(アドレスそのものは会話に書かない)。
   変わった場合は、8 章で設定フォームの説明どおり、検索条件の `from:` を転送元のアドレスにするか、`subject:` の語だけを使う。

届かなければ 3 章に戻る。

## 5. スクリプトの用意

管理者から伝えられた方法で取得し、伝えられた値と一致するかを確かめる。**一致しなければ中止して管理者に相談する。**

- 公開リポジトリの場合: `git clone --depth 1 --branch <tag> https://github.com/<owner>/<repo>.git ~/kakeibo-relay/<tag>` →
  `git -C ~/kakeibo-relay/<tag> rev-parse HEAD` が管理者から伝えられたコミットのハッシュと一致するか。
- 共有フォルダの場合: `mkdir -p ~/kakeibo-relay/<tag>` → `cp -R /workspace/<共有フォルダ名>/. ~/kakeibo-relay/<tag>/` →
  `sha256sum ~/kakeibo-relay/<tag>/relay/*` が管理者から伝えられた 3 つの値と一致するか。

一致したら `ls ~/kakeibo-relay/<tag>/relay` で 3 ファイルがあることを確かめ、利用者に内容を簡単に説明する(聞かれたら `cat` で読んで説明する)。

## 6. clasp で配置

利用者(iPhone):

1. Safari で `https://script.google.com/home/usersettings` を開き、「Google Apps Script API」をオンにする。

Claude(いずれも `cd ~/kakeibo-relay/<tag>` してから):

1. `npx --yes @google/clasp@3.4.1 --version`(3.4.1 と出ること)。
2. `npx --yes @google/clasp@3.4.1 login --no-localhost` を実行し、表示された認可 URL を利用者に伝える。
   - 利用者がその URL を Safari で開き、利用者自身の Google アカウントで許可する。**画面に clasp 以外のアプリ名が出たら許可せず中止**(7 章へ)。
   - 表示されたコード(または開けなかったページの URL 全体)を利用者が会話に貼る。Claude はそれを clasp に渡すだけに使う。
3. 初回: `npx --yes @google/clasp@3.4.1 create-script --type standalone --title 家計簿取込 --rootDir relay`(更新のときは不要。`.clasp.json` はこのディレクトリに残す。秘密ではない)。
4. `npx --yes @google/clasp@3.4.1 push --force`(`relay/` の 3 ファイルでプロジェクトの中身を置き換える)。
5. 初回: `npx --yes @google/clasp@3.4.1 create-deployment --description <tag>`。
   更新: `npx --yes @google/clasp@3.4.1 create-deployment --deploymentId <ID> --description <tag>`(同じ URL を保つ)。
6. `npx --yes @google/clasp@3.4.1 list-deployments` でデプロイ ID を控える。`/exec` の URL は `https://script.google.com/macros/s/<ID>/exec`。
   **この URL はまだ利用者に伝えない**(7 章が終わってから)。

エラーで止めるときも、必ず 7 章を行う。

## 7. 後始末(必須。8 章より前)

Claude:

1. `cd ~/kakeibo-relay/<tag>` して `npx --yes @google/clasp@3.4.1 logout`。
2. `test ! -e ~/.clasprc.json && echo removed` で `removed` が出ることを確認する(`logout` は NAS 上の資格情報を消すだけで、Google 側の許可は取り消さない)。

利用者(iPhone):

3. Google アカウント → セキュリティ →「サードパーティ製のアプリとサービス」(「Google アカウントにアクセスできるサードパーティ製アプリ」等の表示のこともある)を開き、
   clasp(表示名は clasp や Google Apps Script CLI 等)のアクセスを削除する。
4. 削除できたことを Claude に伝える。

Claude は 4 の連絡を受けてから、6 章で控えた `/exec` の URL を利用者に伝える。**取り消しが済むまで 8 章へ進まない。**

## 8. 許可と設定

1. (最初に Claude が)5 章の照合結果(ハッシュが管理者から伝えられた値と一致したこと)を利用者に改めて伝え、置いたコードがその版であることを確認する。
2. 利用者が `/exec` の URL を Safari で開く。
   - 「開けません」等になる場合: Safari で複数の Google アカウントにログインしていると起きることがある。プライベートブラウズのタブで利用者のアカウントだけにログインして開く。
3. 「権限を確認」→ 利用者のアカウントを選ぶ →「このアプリは Google で確認されていません」→「詳細」→「家計簿取込(安全ではないページ)に移動」
   (自分用のスクリプトなのでこの警告が出る)。
4. 同意画面の項目を確認する。**次の 3 項目だけなら「許可」**:
   - メールの表示(Gmail のメールと設定の表示)
   - 外部サービスへの接続
   - ユーザーが不在のときにこのアプリケーションを実行

   **メールの送信・削除・管理、連絡先、ドライブなど、ほかの項目が出たら許可せず中止して管理者に相談する。**
5. 設定フォームが開いたら、利用者が自分で入力する(Claude は値を聞かない):
   - 取込の鍵・家計簿の URL: 管理者から届いた値
   - 検索条件: `from:<カード会社の送信元アドレス> subject:<件名に必ず入る語>` の形(4 章で差出人が変わっていた場合はフォームの説明どおり)
   - 件名の語: 任意
   - お試しモード: **オンのまま**
6. 「保存して開始」→ 状態に「自動の取込: 動いている」と出ることを確認する。
7. 「試す」→「解析できた明細」が 1 件以上なら成功。直近に通知が無ければ 0 件や「見つかりませんでした」になるので、次にカードを使った後にもう一度「試す」。
   「取込の鍵が違います」なら中止して管理者に相談する。

## 9. 本番にする

1. 設定フォームで「お試しモード」のチェックを外し、ほかの欄は空欄のまま「保存して開始」。
2. 次にカードを使ったら、10〜15 分ほどで家計簿に出ることを確認する。
3. 管理者に「設定できた」と伝える。

## 10. 止め方・やめ方

どれも iPhone だけでできる。

- 一時的に止める: 設定フォームの「停止」(設定は残る。再開は「保存して開始」)。
- やめる:
  1. 設定フォームの「すべて削除」。
  2. Google アカウント → セキュリティ →「サードパーティ製のアプリとサービス」で「家計簿取込」のアクセスを削除。
  3. (必要なら)`https://script.google.com/home` でプロジェクト「家計簿取込」をゴミ箱へ(スマホで操作しにくければ残してもよい。許可を取り消せば動かない)。
  4. 3 章で設定した転送・通知先を元に戻す。
- 管理者側で止める: 管理者が家計簿側の鍵を削除する。中継スクリプトは失敗通知(Google からのメール)を出し続けるので、管理者から事前に伝える。

## 11. 困ったとき・更新

### 失敗通知(Google からのメール)が来たとき

- 設定フォームを開き、状態の「最後の実行」の結果を見る。
  - 「鍵が違う」: 管理者に新しい値をもらい、設定フォームの「取込の鍵」だけ入れて「保存して開始」。
  - 「保留あり」: 管理者に連絡する。原因が直ったら「保留を再送」。
  - 「Gmail を読めない」・許可のやり直しを求められる: `/exec` を開き直して許可し直す(8 章の 3〜4)。
- 明細が出ない: 「試す」で「見つかったメール」が 0 なら検索条件か Gmail への転送(3・4 章)を、明細が 0 なら管理者に相談する。

### 更新(管理者から新しいタグ、または新しいファイルとハッシュが届いたとき)

**順番を守る(Gmail を読む許可を先に無くしてから clasp を使う)。**

1. 利用者(iPhone):
   - 設定フォームで「停止」。
   - Google アカウント → セキュリティ →「サードパーティ製のアプリとサービス」で「家計簿取込」のアクセスを削除し、済んだことを Claude に伝える。
2. Claude: 1 が済んだと聞いてから、0 章 → 5 章(新しいタグで取得・照合)→ 6 章(`login` → `push --force` → `create-deployment --deploymentId <ID> --description <tag>`。`create-script` はしない)→ 7 章。
3. 利用者: 7 章の取り消しが済んだら、同じ `/exec` を開いて再び許可する(8 章の 2〜4)→ 設定フォームで**全欄空欄のまま**(お試しモードは今の状態のまま)「保存して開始」(設定は残っているので、トリガーだけ作り直す)。
4. 状態に「自動の取込: 動いている」と出ることを確認する。

更新の間は取込が止まる。止まっていた分は、再開後に直近 7 日の範囲から追いつく。
